# AdminAX LLM 토큰 비용 문제 해결 전략
## AI 모델 3개 협의체 분석 보고서

**작성일:** 2026년 3월 13일  
**대상:** AdminAX 개발팀  
**목적:** 비정형문서 정형화 후 LLM API 과금 문제 해결 방안 제시

---

## 1. 문제 정의

### 1.1 현재 구조의 비용 문제
AdminAX는 비정형문서를 정규화하여 사용자가 최소한의 키워드로 정보를 검색할 수 있게 합니다. 그러나 최종 답변 생성 단계에서 외부 LLM API(예: GPT-4, Claude 등) 호출이 필수적이며, 이는 다음과 같은 비용 문제를 야기합니다.

* **구조적 비용 발생 요인:**
    * **입력 토큰:** 정규화된 문서 컨텍스트 + 사용자 질문
    * **출력 토큰:** 생성된 답변
    * **사용량 증가:** 사용자 수 × 질문 빈도 × 평균 토큰 수
* **리스크:** RAG(Retrieval-Augmented Generation) 구조 특성상 입력 토큰이 비대해지며, 사용자가 늘어남에 따라 비용이 기하급수적으로 증가합니다.

### 1.2 "자체 AI 모델 개발"의 현실성
새로운 파운데이션 모델을 처음부터 학습하는 것은 중소기업 규모에서 비현실적입니다.

| 학습 비용 항목 | 예상 비용 (2026년 기준, USD) |
| :--- | :--- |
| 프런티어 모델 학습 | $100M - $1B+ |
| GPT-4 학습 비용 | $100M+ |
| 중소 규모 모델 (70B) | $6M - $10M |

> **결론:** "자체 모델 개발"은 새로운 파운데이션 모델 학습이 아니라, **오픈소스 모델(Llama, Qwen 등)을 가져와 로컬에서 서빙 및 파인튜닝**하는 것으로 재정의해야 합니다.

## 2. AI 모델 3개 협의체 분석 결과

GPT-5.4, Claude 4.6, Gemini 3.1 세 모델은 **하이브리드 아키텍처(로컬 SLM + 클라우드 LLM 라우팅)**가 가장 현실적인 해법이라는 점에 100% 합의했습니다.

### 2.1 핵심 전략 비교

| 항목 | GPT-5.4 | Claude 4.6 | Gemini 3.1 |
| :--- | :--- | :--- | :--- |
| **로컬 처리 비율** | 규칙+로컬로 대부분 처리 | 80-90% 낙관적 평가 | 70-80% 보수적 추정 |
| **서빙 스택** | 라우팅/캐시 중심 | vLLM (처리량 강조) | Ollama/vLLM 병행 |
| **핵심 인사이트** | LLM 호출 0 구간 확대 | 서빙 성능(동시성) 강조 | 점진적 확장 권장 |

---

## 3. 구체적 해결 방안: 3단계 아키텍처

질의를 3등급으로 분류하여 처리 비용을 최소화합니다.

| 등급 | 처리 방식 | 적용 케이스 | 비용 |
| :--- | :--- | :--- | :--- |
| **1단계** | 규칙 + 템플릿 | 학칙 조회, 표/조항 검색 | $0 |
| **2단계** | 로컬 SLM | 단순 요약, 비교, Q&A | 매우 낮음 |
| **3단계** | 클라우드 LLM | 복잡한 추론, 창작 | 높음 (예외만) |

### 3.1 RAG 최적화 및 캐싱
* **검색 최적화:** top-k 축소(10→3), 재순위화(Rerank), 컨텍스트 압축을 통해 토큰 사용량 30-40% 절감.
* **캐싱 전략:** Redis를 이용한 동일 질의 캐싱 및 의미 기반 유사 질의 캐싱 적용. (최대 81% 비용 절감 사례 존재)

## 5. 단계별 실행 계획 (Roadmap)

1.  **Phase 1 (즉시):** 토큰 사용량 프로파일링, 기본 최적화(max_tokens 제한 등), 캐싱 시스템 구축.
2.  **Phase 2 (1개월):** 질의 유형 분류 및 규칙 기반 템플릿 시스템 구축 (LLM 호출 0구간 확보).
3.  **Phase 3 (3개월):** GPU 서버 도입 및 로컬 SLM(Llama 3.2, Qwen 2.5 등) PoC 및 프로덕션 서빙.
4.  **Phase 4 (기타):** 스마트 라우팅 고도화, 도메인 데이터 파인튜닝, 실시간 비용 모니터링 구축.

## 6. 결론 및 권고사항

AdminAX의 정규화 엔진은 단순히 정보를 찾는 도구가 아니라 **"토큰 절감 장치"**로서의 전략적 가치를 가집니다. 이를 통해 공공기관 및 대학 고객을 타겟으로 한 **"완전 온프레미스 AI"** 옵션을 제공할 수 있으며, 이는 시장에서의 강력한 경쟁력이 될 것입니다.
